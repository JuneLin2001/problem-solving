### 解題思路

呈上題 [3903. Smallest Stable Index I](../3903.%20Smallest%20Stable%20Index%20I/README.mdx) 的解題思路，若直接用同做法會因為測資較大而超時。

上題的解法是每次都重新計算 `maximum` 和 `minimum`，故要提升效率可以從此著手改善。

首先要改的是 `maximum` 的部分。  
目前是每次都重新計算，但可以用一個變數儲存目前最大值，當遇到更大的數時就更新這個值。

```js
let maximum = 0;

for (let i = 0; i < n; i++) {
  maximum = Math.max(maximum, nums[i]);
}
```

至於 `minimum`，可以先建立一個陣列 `suffixMin`，用來儲存「從目前 index 到最右邊」的最小值。  
因為 `suffixMin[i]` 的計算方式是：

```js
suffixMin[i] = Math.min(nums[i], suffixMin[i + 1]);
```

也就是說，`suffixMin[i]` 的計算需要先知道右邊的 `suffixMin[i + 1]`。  
因此我們必須先從最右邊開始計算，再一路往左建立 `suffixMin`。

接著才能依序計算 `suffixMin[n - 2]`、`suffixMin[n - 3]`……直到 `suffixMin[0]`。  
如果從左到右計算，就會發現當我們要計算 `suffixMin[i]` 時，右邊的 `suffixMin[i + 1]` 還沒有被計算出來，因此無法使用這個公式。

```js
const n = nums.length;

const suffixMin = new Array(n); // 直接建立一個長度為 n 的陣列
suffixMin[n - 1] = nums[n - 1]; // 最右邊的 suffixMin[n - 1] 沒有右邊的元素，所以它的最小值就是自己

// 從右往左建立 suffixMin
for (let i = n - 2; i >= 0; i--) {
  suffixMin[i] = Math.min(nums[i], suffixMin[i + 1]); // 當前數字和右邊的最小值比較，取較小的
}
```

所以整體的邏輯就是先算好所有的 `minimum`，再從左往右算 `maximum`。
最後才能計算：

```js
maximum - suffixMin[i];
```

也就是題目要求的：左邊最大值 - 右邊最小值
